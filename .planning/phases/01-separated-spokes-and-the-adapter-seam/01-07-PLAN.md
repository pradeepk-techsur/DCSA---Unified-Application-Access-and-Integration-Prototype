**The ten assertions, from `FR-F08a-08` / `TechArch §14.4`:**

| # | Assertion |
|---|---|
| 1 | **Interface completeness** — operations 1-7 present; optional operations (`getWorkItemSummary`, `establishContext`/`revokeContext`) present **iff** declared in `describe().capabilities`. |
| 2 | **`describe()` schema validity** — validates against `DescribeResult`; **every** native status the spoke can emit is mapped to exactly one `statusCategory`; every `actions[].requiredPermission` exists in the role matrix (`hub.permissions`). |
| 3 | **Normalization** — every returned `WorkItem` satisfies the normalized shape; `workItemId` is `${sourceSystem}:${nativeId}`; priority and status mapping correct; `priorityProvided` reflects `priorityNative`. |
| 4 | **Scope enforcement** — a scoped list for subject A returns **zero** rows belonging to subject B; a scoped get for a foreign resource returns `ADAPTER_NOT_FOUND` or `ADAPTER_FORBIDDEN`, **never data**. |
| 5 | **Deadline honouring** — a call with a 100 ms deadline aborts within 150 ms. |
| 6 | **Error taxonomy** — induced connection refusal, timeout, 4xx, 5xx and a malformed response each produce the correct `AdapterError` class. Use the spoke's `/admin/injection` control (`UNAVAILABLE`, `SLOW`, `ERROR`) plus a deliberately-wrong endpoint for the refusal case. |
| 7 | **Idempotency** — `performAction` repeated with one key applies **once**. |
| 8 | **`stateVersion` progression** — changes after a mutation, stable otherwise. |
| 9 | **No cross-spoke access** — the adapter's outbound calls target only its own application's base endpoint. Implement by wrapping `globalThis.fetch` for the duration of the run and asserting every request URL's origin equals the configured `baseEndpoint` origin. |
| 10 | **Health semantics** — `healthCheck()` returns `DOWN` promptly when the spoke is stopped and `HEALTHY` after restart. Drive the stop/start through `/admin/injection UNAVAILABLE` → `NORMAL` so the suite stays runnable without container control; document that the process-stop variant is exercised by `./run.sh stop <svc>` in the Phase-8 resilience suite. |

**Behavioral assertions across adapters** (`TechArch §14.4`, run when the suite is invoked for all
five): a `SLOW` spoke still returns the aggregate within budget; transient read failures retry per
policy while `performAction` timeouts **never** do; the circuit opens at the threshold, fails fast,
continues health probing, and closes on a successful probe; malformed items are dropped
**individually** with an issue logged while the batch still renders.

**Mutating assertions must be self-cleaning.** Assertions 7 and 8 perform real writes. Each must
target a **designated conformance fixture record** (not `ISS-2207`, not `CASE-A-1042` — consuming a
flagship precondition inside a test suite is exactly the demo-day failure `FR-F17-11` exists to
prevent) and the suite must restore the record's prior state in teardown, or instruct the caller to
run `./run.sh reset`. Pick the fixture per application from the seeded corpus and name it in
`docs/SEED-DATA.md`'s conformance section.

`FR-F19-09`), one line per assertion with the adapter name, and a summary line. Exit non-zero on any
failure. A failing assertion must say what is wrong **actionably** — e.g.
`PVQ assertion 2 FAILED: native status 'ESCALATED' is not present in statusMap for type PVQ_ISSUE`,
not `expected undefined to be defined` (`FR-F08a-08` AC-3).

**`src/cli.ts`** — `--adapter=<APPLICATION_ID> --endpoint=<url>`; it loads the registry row for that

candidate adapter can prove itself **before** it is registered — which is precisely the Phase-7 gate
(`FR-F12-04` runs items 1, 2 and 6 live during registration).
