<objective>
Make the hub's knowledge of "which applications exist" a property of a database table rather than of
its source code, and enforce that mechanically. Deliver the registry service, the adapter factory,
the single scoped call site through which the hub may reach a spoke, the registry-driven fan-out, and
the CI gates that fail the build if a spoke identifier is ever hard-coded into hub core or an HTTP
call is ever aimed at a spoke from outside an adapter package.

Purpose: this is **success criterion 4 of the phase** and the thing Phase 7's live registration plugs
into. If it is not true here, extensibility becomes a retrofit. It is also, per ADR-016, the claim
most likely to erode by the third sprint — which is why it is a build-failing grep rather than a
convention.
Output: `apps/hub` (registry + gateway + minimal process) and `scripts/arch-check.sh`.
</objective>

interface RegistryService {
  all(): RegistryRecord[];                          // enabled and disabled — the admin inventory
  enabledFor(role: RoleId): RegistryRecord[];       // enabled === true AND role ∈ visibleToRoles

}

Every registry-derived behavior in `FR-F08b-02`'s table reads through this object. `enabledFor` is the

**`src/registry/factory.ts`** — instantiation **by `adapterType`**:

This map is the **only** hub-side code change a seventh backend kind requires
(`TechArch §17.5` step 2: "one line in one map"). An `adapterType` absent from the map makes the row

**`src/registry/validate.ts`** — startup validation per `FR-F08b-06` rule 1. For every row check:

`workItemTypes[].statusMap` non-empty.

excluded from every user-facing surface, and surfaced for the admin console (Phase 6). **The hub
still starts** — one bad row must not prevent the demo — but the condition is loudly visible in the
startup log, not silent.

hub starts anyway. An unsupported `contractVersion` marks the row `INCOMPATIBLE` and excludes it.

**`src/spoke-gateway/gateway.ts`** — choke point 2 from `TechArch/01-components.md §1.3`. Transcribe
the function, including its comments:

```ts
export async function callSpoke<Op extends AdapterOperation>(
  principal: Principal,
  applicationId: string,
  operation: Op,
  args: AdapterArgs<Op>,
  ctx: RequestContext,
): Promise<AdapterResult<Op>> {
  const scope = deriveScope(principal);                 // FR-F02-04 rule 1
  if (!scope) throw new InternalError('SCOPE_ABSENT');  // fail closed, never permissive
  const adapter = registry.instanceFor(applicationId);  // throws if disabled/unregistered
  const result = await adapterRuntime.invoke(adapter, operation, args, {
    principal, scope, correlationId: ctx.correlationId, requestId: ulid(),
    deadlineAt: ctx.deadlineFor(applicationId, operation),
    idempotencyKey: isMutating(operation) ? args.idempotencyKey : undefined,
  });
  return enforceScopeOnResult(scope, applicationId, result, ctx); // defense in depth
}
```
**This is the ONLY function in the hub that may invoke an adapter.** Hub core modules import
`callSpoke`; they do not import adapters and they do not import an HTTP client — enforced by the
ESLint `no-restricted-imports` rule from plan 01-01 and the grep in Task 3.

`ctx.deadlineFor(applicationId, operation)` reads `timeoutMs` / `actionTimeoutMs` / `healthTimeoutMs`
from the registry row — **never a constant in this file**.

**`src/spoke-gateway/scope.ts`** — `deriveScope(principal)` per the `Scope` union in
`@ual/adapter-contract`: `APPLICANT` → `{ mode:'SUBJECT', subjectRef }`; `INVESTIGATOR`/`ADJUDICATOR`
→ `{ mode:'ASSIGNEE_OR_UNIT', principalId, organization, assignedRegion }`; `ADMINISTRATOR` →
`{ mode:'NONE' }` (platform resources only, no work items). An APPLICANT with a null `subjectRef`
returns `null`, which makes `callSpoke` fail closed. Also implement `enforceScopeOnResult` —
defense in depth: rows outside scope are dropped and an `ADAPTER_SCOPE_VIOLATION` issue is recorded,
while the request otherwise succeeds (`FR-F08a-06`).

**`src/spoke-gateway/fan-out.ts`** — the generic, registry-driven concurrent fan-out:
```ts
export async function fanOut<Op extends AdapterOperation>(
  principal: Principal, operation: Op, args: AdapterArgs<Op>, ctx: RequestContext,
): Promise<{ results: Array<AdapterResult<Op>>; sourceStatus: SourceStatus[] }>
```
It iterates `registry.enabledFor(principal.activeRole)` — **there is no literal list of applications
anywhere in this file or any file it imports from hub core.** Calls run concurrently; **one failing
source never fails the whole call** (`TechArch §1.2`: the aggregator "must not fail the whole request
because one source failed"). Each source contributes a `SourceStatus`
`{ applicationId, displayName, outcome: 'OK'|'FAILED'|'SKIPPED', errorClass?, itemCount }` so a later
phase can render a named, quantified degraded warning. The full queue semantics (normalization
validation, merge, sort, filter, paginate) are **Phase 4**; what ships here is the fan-out primitive
and its partial-failure contract.

**`src/server.ts`** — the minimal hub process. Fastify 5.2.0, bound
`host: process.env.UAL_BIND_HOST ?? '0.0.0.0'`, `port: Number(process.env.PORT ?? 7100)` —

(`TechArch §15.4`):
