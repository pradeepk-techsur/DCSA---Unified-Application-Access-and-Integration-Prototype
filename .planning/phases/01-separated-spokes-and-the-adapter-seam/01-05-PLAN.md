<objective>
Build the synthetic corpus every later screen renders: deterministic, idempotent, never stale,
referentially coherent across namespaces that share no table, obviously fabricated, and
self-validating. Ship the validator that **fails startup** on broken data and the reset command that
restores baseline in under 30 seconds.

Purpose: the seed is not test fixtures — it is the demonstration's stage. A flagship workflow whose
preconditions were consumed on the previous run is a demo that fails in front of a reviewer, and a
demo starting on broken data is worse than one that refuses to start.
Output: `@ual/seed` (generator, per-namespace writers, manifest, validator, reset) and
`docs/SEED-DATA.md`.
</objective>

**`src/rng.ts`** — `createRng(seedConstant)` over `pure-rand`'s `xoroshiro128plus`, seeded from
`UAL_SEED_CONSTANT` (`DCSA-UAL-2026-09-14`). Every generated value — identifiers, names, dates,

**`src/dates.ts`** — `offsetFromReference(daysOffset)`: relative dates derive from
`UAL_SEED_REFERENCE_DATE` (`2026-09-14`), then are **offset against the current date at seed time**,
so "overdue by 6 days" stays overdue whenever the demo runs, in 2026 or 2027 (`FR-F17-05` rule 2).
Never call `Date.now()` for a domain date.

**`src/write.ts`** — the load-bearing detail from `TechArch §13.2`: **the writers use each
namespace's own credential.** The seeder does NOT connect as the database owner and write everywhere;

exercised by the very first thing that touches the database — if a grant were wrong, seeding fails
before any demo runs. Each namespace is truncated and rebuilt **within one transaction per namespace**
so running the seeder twice leaves the environment identical, never duplicated (idempotent).
