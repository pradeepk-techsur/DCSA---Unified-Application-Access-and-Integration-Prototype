Build the five mission systems as genuinely separate, independently callable services: one shared
`@ual/spoke-kit` implementing the common spoke contract once, plus five thin domain modules over five
isolated namespaces with five distinct credentials.

Purpose: "a spoke behaves correctly" must be one implementation verified once, not five
implementations verified five times — and each spoke must be independently stoppable so that "what
happens when Investigation Management is down" is a real experiment rather than a description.
Output: `@ual/spoke-kit` and `services/{eapp,pvq,iep,pdt,im}`, each with an integration test suite
that runs against a real PostgreSQL.

**Error mapping (`FR-F09-07`, `Y1b`, `TechArch §7.1`) — implement exactly:**
`400 SCOPE_REQUIRED` · `400 VALIDATION_FAILED` · `401 PRINCIPAL_REJECTED` · `403 FORBIDDEN` ·
`404 NOT_FOUND` · `409 IDEMPOTENCY_KEY_REUSED` · `409 STATE_CONFLICT` · `422 ACTION_REJECTED` ·
`429 RATE_LIMITED` · `503 SERVICE_UNAVAILABLE`. `message` is plain language and safe to surface **only**
for `ACTION_REJECTED`.

**⚠️ RECORDED CONFLICT RESOLUTION — evaluator `curl` ergonomics vs mandatory headers.**
`TechArch §7.3` documents the direct-verification call as carrying only `X-UAL-Principal`, while
`FR-F09-07` rule 2 and `Y1b` make `X-UAL-Scope` (reads) and `X-UAL-Deadline` mandatory. Resolution,
which satisfies both without ever permitting an unscoped read:
- **Scope** — if `X-UAL-Scope` is absent, the kit falls back to a `scope` claim embedded in the
  assertion (operator tokens minted by `mintOperatorToken` carry one). If neither is present the
  request is refused `400 SCOPE_REQUIRED`. There is no permissive default.
- **Correlation / request id** — if absent, the kit generates a ULID (the adapter always sends them).
- **Deadline** — if absent, the kit defaults to `now + 5s`. An explicit header always wins and is
  always honoured.
Adapters continue to send all six headers on every call; the fallbacks exist solely so the documented
`curl` in `TechArch §7.3` works verbatim for a reviewer. Record this in the SUMMARY.

**Prohibitions, enforced by the kit and by test (`TechArch §1.4`):** a spoke has **no outbound HTTP
client at all**. `@ual/spoke-kit` does not export one and MUST NOT depend on `undici`, `node-fetch`,
`axios`, `got`, or `superagent`. A spoke cannot call another spoke because it has nothing to call with.
The kit also MUST NOT emit `X-Frame-Options` or a CSP `frame-ancestors` directive (**ADR-012**).

Bind to `process.env.UAL_BIND_HOST ?? '0.0.0.0'` and `process.env.PORT` — **never `localhost`**; a
localhost bind inside a container makes the service unreachable from the host.

**`CLEAR_OUTSTANDING_ISSUE(issueRef)` — the behavior that makes the flagship retry safe

zero, `case_state` moves `UNDER_REVIEW → REVIEW_COMPLETE_PENDING_ADJUDICATION` and exactly one
`eapp.case_activity` row is written. Request shape from `Y1b`:
`{ issueRef, resolvedDisposition, stateVersion }` → `{ outcome, case, stateVersion, appliedAt, _synthetic }`.

Scope enforcement (`FR-F09-02`): `mode: SUBJECT` → cases matching `subject_ref`;
`ASSIGNEE_OR_UNIT` → cases assigned to the principal OR matching `organization` + `region`;
`ORG` → cases in the organization. **The predicate is injected into the SQL in
`domain/repository.ts`, visibly** — no ORM, hand-written SQL (ADR-005), because the reviewer must be
able to read the `WHERE` clause.

`describe()` declares work-item type `EAPP_CASE_REVIEW`, relationship types `HAS_ISSUE`,

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| hub→spoke (client→API) | Untrusted request data — headers, path params, query params, action payloads — crossing into a spoke handler |
| operator→spoke | An evaluator's `curl` with a short-lived operator token crossing into the same handlers |
| spoke→own schema | Handler-supplied scope and identifiers crossing into hand-written SQL against one namespace |
